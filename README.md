# context-audit

**给你的 Agent 做一次上下文工程体检，让它少读无关资料，清楚地执行任务。**

好的上下文工程，让 Agent 在需要的时候拿到必要的信息：减少不必要的 Token 消耗，同时保留完成任务所需的规则与资料。

context-audit 检查全局提示词、项目提示词及其引用的规则与索引，找出指令含糊、规则冲突、引用失效、读取范围不合理等问题，提供带原文证据的改进建议。

## 支持范围

目前内置 **Codex、Claude Code** 的指令文件机制参考，支持检查 `AGENTS.md`、`CLAUDE.md` 等入口及其明确引用的规则。

同一个项目同时使用多个 Agent，也可以分别识别规则的适用范围。其他客户端可进行有依据的文字检查，但尚未提供专门适配。

## 检查项目与判断方法

| 检查项目 | 判断方法 |
|---|---|
| **规则职责与作用范围** | 对照文件职责和规则用途，检查只适用于某个项目或任务的要求，是否被扩大为全局要求。 |
| **指令清晰度** | 检查是否缺少执行所需的条件、对象、动作、权限或完成标准，导致 AI 必须猜测，且不同猜法会改变结果。 |
| **规则冲突** | 检查同一场景下同时生效的要求，是否无法共同满足，并核对是否已有例外或覆盖规则。 |
| **重复与版本漂移** | 区分共享引用与独立维护的副本，检查重复规则是否出现版本不一致、真源不清或同步风险。 |
| **循环依赖** | 沿强制前置关系查找闭环，检查是否存在互相等待，且缺少起始条件或退出机制。 |
| **引用有效性** | 核对指定文件、章节及工具入口，区分确实缺失、路径不明、访问受限和运行未验证。 |
| **上下文加载范围** | 对照资料用途和读取条件，识别特定任务资料被要求每次加载等范围不匹配；不会仅凭文件长度判定内容多余。 |
| **索引与路由维护** | 检查何时读取哪些资料、读取边界是否明确，以及文件改名、迁移后，相关索引和引用如何更新。 |

每项先判断是否适用，再判断是否存在问题。没有索引，不会因此被判为缺陷。

检查从当前工作目录出发，定位适用的用户级全局指令、项目指令，再沿明确引用展开相关规则；不会扫描整个项目或知识库。

## 体检报告

每条发现都包含：

| 位置与原文证据 | 问题 | 原因与影响 | 具体改进建议 |
|---|---|---|---|

例如，指令写着“重要修改先确认”，却没有定义“重要”。报告会指出缺少审批触发条件，并提出需要澄清的内容，不擅自替用户设定门槛。

报告区分**明确问题、可能风险和可选建议**，同时说明检查范围与未能确认的部分。Skill 只做检查，由你审核并决定是否修改。

## 安装

将下面这段话发送给支持 Skill 安装的 Agent：

> 请阅读 https://github.com/william854014048-ops/context-audit 的 README，并安装 context-audit。Skill 位于仓库根目录，请完整获取 SKILL.md、references/ 和 agents/，安装后核对配套文件是否齐全，不要只复制 SKILL.md。

如果安装器采用 Git 稀疏检出，选择仓库根目录可能遗漏子目录。请使用完整下载或完整克隆，并核对文件。
