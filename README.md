# context-audit

给 Agent 的指令与上下文做一次只读体检，找出指令含糊、规则冲突、失效引用和加载范围不明确等问题，交付带证据的报告，由你决定是否修改。

从当前工作目录开始，检查适用的用户级全局提示词、项目提示词，以及它们明确引用的规则和索引。不会扫描整个知识库，也不要求项目必须有索引。

## 安装

这是一个私有仓库。安装者必须拥有仓库访问权限，且执行安装的环境已完成 GitHub 认证；只有链接无法获得访问权限。不要在聊天中粘贴访问令牌。

在能读写本机文件、支持 Skill 的 Agent 中发送：

> 请从 https://github.com/william854014048-ops/context-audit 安装 context-audit。先阅读 README。Skill 位于仓库根目录，目标文件夹命名为 context-audit。完整获取 SKILL.md、agents/ 和 references/，按照当前客户端的 Skill 目录规范安装；不要仅复制 SKILL.md，不要覆盖已有同名安装。最后核对下面列出的五个文件及 SKILL.md 的相对引用。如果没有私有仓库访问权限，请明确告诉我。

### 给安装 Agent 的说明

本仓库根目录就是 Skill，不是包含多个 Skill 的集合。Codex 的 skill-installer 可以使用以下参数（脚本路径以本机实际安装位置为准）：

```text
install-skill-from-github.py --repo william854014048-ops/context-audit --path . --name context-audit --method download
```

私有仓库下载需要安装器支持的已授权认证环境。若只能使用 Git 凭据，可完整克隆仓库，再将以下五个文件按原目录结构复制到目标 Skill 文件夹，排除 `.git/`。不要对仓库根路径 `.` 使用稀疏检出安装后直接判定成功：本次实测该路径可能遗漏子目录。

安装后应包含：

```text
context-audit/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── criteria.md
    ├── client-codex.md
    └── client-claude-code.md
```

`SKILL.md` 是执行入口；`criteria.md` 是检查判据；两个客户端参考文件用于解释相应指令机制；`openai.yaml` 是 Codex 界面与调用配置。README 是安装说明，可保留在安装目录中。此 Skill 不包含需要运行的业务脚本，不依赖额外服务。

## 使用

进入想检查的工作目录，明确调用：

> 使用 $context-audit 检查当前工作目录适用的全局、项目提示词及其规则引用，只报告，不修改。

报告包括问题位置与证据、原因与影响、具体建议，以及已检查范围和未能确认的部分。主要检查：

- 文件职责、指令是否缺少执行所需信息。
- 共同生效的规则是否冲突、重复，强制前置关系是否形成循环。
- 引用是否有效，内容用途与加载条件是否匹配。
- 存在路由或索引时，其选择条件、引用与维护规则是否清晰。

## 验证与边界

2026-09-10：使用 Codex 自带 skill-installer，在已授权环境中通过下载方式安装到隔离目录，核对五个文件完整性。Git 稀疏检出仓库根目录的方式曾返回成功但遗漏配套目录，因此安装必须核对文件，不能只看成功提示。

安装包完整不代表所有客户端的发现、加载和真实执行都已验证。Skill 内提供 Codex 与 Claude Code 的指令机制参考，其他客户端需核对其安装与调用方式。

本工具只做静态检查；不会自动修改文件，不能据此证明实际 Token 消耗、费用、缓存或任务效果得到改善。体检结束后是否修改，由用户另行决定。
