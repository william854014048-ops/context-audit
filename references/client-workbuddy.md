# WorkBuddy 入口与检查边界

更新日期：2026-09-10。本表根据用户提供的 WorkBuddy 本机目录梳理建立，用于定点发现候选；不是厂商对所有版本的文件与自动注入契约。用户描述身份文件每会话注入、项目 AGENTS.md 作为 project guidance，但具体会话仍须有加载证据，不能以文件存在代替。产品名 WorkBuddy；用户写 Workbody 时可结合语境识别，不与 CodeBuddy 混同。

官方依据：[系统设置](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Setting)确认应用提供自定义指令，并在代码开发时兼容用户级 .codebuddy 配置；[记忆说明](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Memory)确认记忆由会话提取并随任务参考。两页未为下面每个本地文件规定统一注入次序或优先级，不把本机目录报告升级成官方规则。

## 定点发现

用户目录优先使用宿主明确提供的位置，否则以当前用户主目录下的 .workbuddy 为候选；不硬编码用户名，不发明环境变量，不枚举其他用户。项目根使用宿主明确工作区或已确认的项目根线索；只有当前目录可确定时先按局部范围探测，不能搜索所有 projects/ 来猜根目录。

以下七个文件分别探测。缺少其中一个不阻止其余检查；不存在不要求创建，BOOTSTRAP.md 不存在也不算缺失初始化。

| 候选位置 | 角色与检查内容 |
|---|---|
| ~/.workbuddy/SOUL.md | 行为原则与人格约束：规则清晰度、权限及与其他已知有效规则的关系。人格描述本身无需变成执行步骤。 |
| ~/.workbuddy/IDENTITY.md | Agent 身份：身份与职责是否明确，是否夹带作用范围不明的业务要求。 |
| ~/.workbuddy/USER.md | 用户信息与偏好：区分事实、偏好和强制规则，不将个人背景不完整判为指令缺陷。 |
| ~/.workbuddy/BOOTSTRAP.md | 初始化引导：触发、完成与退出条件；只有证据表明已完成却仍要求反复初始化时才报告，不因文件存在建议删除。 |
| ~/.workbuddy/MEMORY.md | 用户级长期记忆：区分现行约定与历史／事实，检查夹带规则的范围、读取条件及引用；不评价所有记忆内容是否值得保留。 |
| <项目根>/AGENTS.md | 项目指导：检查本项目规则与其显式引用；无证据时不沿用 Codex 的覆盖顺序或自动读取机制。 |
| <项目根>/.workbuddy/memory/MEMORY.md | 项目长期记忆：检查项目约定、历史与现行要求的区分，以及被引用的规则；不因没有 AGENTS.md 就跳过。 |

在两份 MEMORY.md 与身份入口中发现的显式规则／索引引用，同样按主 Skill 的范围与预算继续展开。共享 AGENTS.md 正文可以复用，但不能因此判两个客户端都实际加载，或自动把其规则当成同等优先级。

表中角色是本机目录模型提供的职责线索；审查时仍用 C1 对照当前文件声明与正文，不因 USER.md 含必要行为偏好、MEMORY.md 含现行约定就判放错文件。依 C7 分别记录「客户端→身份／记忆入口」「项目指导→规则」「MEMORY→索引→规则」等已发现关系；每会话注入的本机报告不代表所有版本或所有引用目标都会全文加载。

## 应用设置与兼容配置

- 平台「自定义指令」独立于上述文件记录。当前会话有明确标识的可见正文或已有只读导出时，按指令检查；不可取得时标「未覆盖：应用设置正文不可见」。不读取隐藏厂商提示词，不搜索数据库／会话记录来反推。
- 本机目录梳理未发现 ~/.workbuddy/AGENTS.md 或 CLAUDE.md；不把二者列为必备文件，也不因缺少而漏掉五个用户级入口。有明确引用则正常检查，不声称所有版本绝不支持。
- 本机 settings.json 被报告为通道配置；不为了找指令读取其中凭据，也不把这个观察当作所有版本的固定 schema。
- 官方说明代码开发会兼容 .codebuddy。当前已有代码开发模式／明确配置证据时，可沿已知规则入口继续；具体入口与机制未确认则单列「代码开发兼容规则未覆盖」。不能把“支持 WorkBuddy”理解为所有 CodeBuddy 模式都已适配，不借此遍历 .codebuddy 的全部能力与运行目录。

## 不默认展开的内容

| 路径类别 | 处理 |
|---|---|
| <项目根>/.workbuddy/memory/<日期>.md | 日志，不扫描全部历史。入口明确指向的具体日志／日期范围才按需查阅规则片段；范围无法确定时记录待定位，不自行读取整个目录。 |
| ~/.workbuddy/memory/<uuid>_memory.md 及 .bak | 本机报告为云记忆缓存及备份，默认不枚举。明确引用具体目标时可只读审查相关部分，保留服务端来源，不建议将缓存改成手写真源。 |
| ~/.workbuddy/memery/user-memery-state.json | 本机报告的状态文件；保留实际拼写，不纠正成 memory，不当指令入口。 |
| 用户／项目 skills/，plugins/、connectors/、extensions/ | 能力目录，不全量扫描已安装 Skill；仅沿入口明确引用的规则文件读取。 |
| mcp.json、.mcp.json | 工具配置；仅在具体规则依赖核实确有需要时检查必要入口字段，不回显凭据，不做 MCP 安全审计。 |
| workbuddy.db、automation-backups/、binaries/、sessions/、tasks/、todos/、plans/、projects/、logs/、file-history/、audit-log/、traces/ | 运行／历史数据，不因位于 .workbuddy 下就纳入体检，不启动运行时、不读取数据库、不巡查定时任务。 |

未知文件职责先保留未知；历史日期、文件大小、没有定时清理均不能单独证明上下文负担过重。建议限于澄清、定位、分层与维护候选，不替用户删除、迁移、重写记忆或修改设置。
